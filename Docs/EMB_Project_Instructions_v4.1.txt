Назначение и текущая стадия
Enfusion Map Builder (EMB) — поиск и сборка бесплатного, качественного и воспроизводимого рабочего процесса создания карт для Arma Reforger; перенос на Arma 4 оценивается отдельно. EMB не обязан стать приложением, собственным terrain engine или фиксированной архитектурой.
СЕЙЧАС: исследование и прототипирование (этапы A–B). Рабочий Synthetic pipeline и полный сквозной playable-мир ещё не подтверждены. Не трактовать кандидатные инструменты и гипотезы как принятые решения. Допустимы возвращение к поиску, смена инструмента и переоценка ранее сделанных выводов.

Два режима принятия решений
1. Исследование / прототипирование (текущий режим). Приоритет — быстро находить хорошие решения, сравнивать подходы и проверять только существенные неизвестные. Для нового вопроса сначала выполнить целевой поиск готовых бесплатных вариантов: штатные возможности Reforger, Workshop/GitHub, внешние программы и библиотеки — по релевантности задачи. Не требуется завершать полный аудит всех категорий ради чтения документации, изучения интерфейса, настройки готового инструмента или малого изолированного эксперимента. Можно пробовать разные гипотезы, инструменты, GUI, CLI и готовые MCP, не ограничивая исследования заранее выбранным списком. Результат коротко фиксировать: гипотеза → что проверено → вывод/ограничение → следующий шаг.
2. Постоянный компонент / production workflow (после проверки гипотезы). Перед созданием и включением собственного Workbench Plugin, Enforce Script, Python/PowerShell-инструмента, terrain generator, importer/exporter, backend, adapter, MCP-layer или другого функционального компонента ОБЯЗАТЕЛЕН полный Audit Gate. Никакой proof-of-concept или тест API не заменяет этот аудит. Рабочий стек утверждается только по результатам практического использования; поддерживаемость, лицензии и воспроизводимость становятся критериями принятия.

Audit Gate перед собственной функциональной реализацией
1. Определить конкретный результат и критерии успеха.
2. Проверить штатные Arma Reforger Tools / Workbench / World Editor: Terrain Tool, Shapes/Splines, Road/Lake/River/Forest/Prefab Generators, FG/PG, Navmesh, материалы, import/export и официальные Samples.
3. Проверить релевантные бесплатные Workshop-инструменты.
4. Проверить актуальные бесплатные GitHub/community-проекты.
5. Проверить специализированные бесплатные terrain/GIS/DCC-решения (например, QGIS/GDAL, GRASS GIS, WhiteboxTools, Blender, TerreSculptor, другие новые кандидаты), зрелые библиотеки и готовые API/CLI/MCP.
6. Сравнить качество, актуальность, совместимость, бесплатность, лицензии и права на использование, зависимости, документацию, автоматизацию и воспроизводимость.
7. Небольшая проверка подходящих решений. До собственного кода записать, что не подошло, почему и какой минимальный пробел остаётся.

Граница между прототипом и разработкой
Временные исследовательские команды, диагностические пробы и короткие одноразовые скрипты допускаются для оценки существующих инструментов, форматов и API после быстрого предметного поиска готового способа. Их не следует превращать в пользовательскую функцию, самостоятельный генератор, импортёр или постоянный слой EMB до полного Audit Gate. Такие пробы не считаются подтверждением отсутствия готового решения и по окончании удаляются, если не содержат необходимого воспроизводимого результата.
Не создавать заранее Core, WorldModel, Terrain Backend, Asset Resolver, Adapters, отдельный GUI или собственный MCP. Не повторять успешные тесты без нового основания. Этапы A–B допускают циклы и смену направления, а не служат последовательными запретами.

Бесплатность и распространение
Карты распространяются бесплатно; добровольная поддержка автора через Boosty/донаты не является условием доступа к картам, ранним версиям или игровому содержимому. Не предлагать за пожертвования внутриигровые эксклюзивы и преимущества. При публикации сверяться с актуальными правилами Bohemia Interactive, Workshop и лицензиями конкретных инструментов/ассетов. Бесплатность программы сама по себе не гарантирует допустимость любого использования. Платные заказы и коммерческое использование BI Tools оцениваются отдельно; донаты не отменяют лицензии.

Synthetic и RealWorld
Synthetic: оригинальные игровые миры; игровой процесс важнее чистой геологической правдоподобности. Любой перспективный бесплатный генератор может быть исследован; LibreTerrain — кандидат, НЕ утверждённый backend. Принятые heightmap/masks, исходники, параметры и seed сохраняются, когда доступны. Художественные и LD-решения принимает человек.
RealWorld: актуальные официальные GIS/DEM/ортофото — для геометрии, OSM/векторы — дополнение, исторические карты и фотографии — контекст. Ruhnu — отдельный проект; он не задаёт структуру Synthetic. Base Map Generator NG — кандидат, не принятый стек.

Данные, уборка и безопасность
Разделять Source / Working / Output / Code / Docs / Workbench / Backups при реальной необходимости, а не создавать пустую архитектуру папок. Не перезаписывать Source. Сохранять принятые исходники, параметры, версии, настройки и критические результаты. Удалять одноразовые эксперименты/кэши после извлечения выводов; не хранить библиотеку всех попыток. Перед массовыми изменениями и удалением проверять точный состав, зависимости, Git tracked/untracked и данные вне Git; согласовывать разрушительные действия, использовать Git/backup. Проверять на малой области, но не превращать работу в бесконечную серию тестов.

Практическая работа и общение
Русский язык, чёткие шаги; для PowerShell всегда указывать вкладку «EMB — Commands». Сначала простейший штатный путь. Для Reforger/Workbench/Workshop/GitHub/MCP/GIS, API и лицензий проверять меняющиеся сведения по первичным источникам. Разделять «написано в документации», «заявлено автором» и «проверено нами». Codex помогает исследовать, сравнивать, готовить данные и проверять решения; финальные решения по Level Design/Art принимает пользователь.

Этапы и критерий успеха
СЕЙЧАС A–B: исследование ↔ небольшие проверки, возврат и смена кандидатов допустимы. C — один сквозной playable production-test; D — минимальный подтверждённый pipeline; E — автоматизация узких мест; F — собственный production-код лишь для доказанных пробелов; G — развитие.
Цель — качественные бесплатные карты с минимальным количеством лишних зависимостей, собственного кода и накопленных экспериментов. Не считать скорость перехода к этапу C важнее качества выбранного подхода.
