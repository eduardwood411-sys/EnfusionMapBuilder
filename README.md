# Enfusion Map Builder

Проект по поиску, проверке и сборке качественного, воспроизводимого, удобного и повторно используемого процесса создания игровых миров для Enfusion. Gameplay suitability важнее чистой геологической правдоподобности.

## Направления

**Synthetic — приоритет:** оригинальные синтетические миры. Входами в зависимости от выбранного workflow могут быть brief / текстовое описание, seed и параметры, reference, изображения и маски, AI-результаты, конфигурации внешних generators / terrain tools. Seed и параметры сохраняются там, где выбранный инструмент их предоставляет. Цель — достаточная воспроизводимость выбранного production-варианта; seed не обязателен для каждого workflow. **RealWorld — вторичное направление:** реконструкция реальных территорий. Для RealWorld приоритет источников: официальные актуальные GIS → DEM/orthophoto → OSM/vector → historical/visual references.

Эти направления могут использовать разные workflows. Ruhnu — отдельный RealWorld production/test case, который не определяет архитектуру Synthetic.

Текущий production workflow проектируется вокруг бесплатного toolchain, без обязательных paid dependencies.

## Research-first подход

Требуемый результат → поиск готовых решений → сравнение → малый практический тест → выбор workflow → интеграция/адаптация → собственный код только для подтверждённого пробела.

Исследуются официальные возможности Bohemia Interactive / Enfusion / Workbench, Workshop, GitHub/community, зрелые terrain tools, QGIS/GDAL/GRASS/WhiteboxTools, GeoPandas/Shapely/NumPy/SciPy, OSM, AI/ChatGPT/ComfyUI и другие подходящие решения. Перед автоматизацией Reforger проверяются встроенные World Editor / Workbench инструменты и способы импорта.

Enfusion Map Builder не обязан стать единым приложением или фиксированным набором модулей: результатом могут быть конфигурации, интеграции, небольшие скрипты, адаптеры и внешние инструменты. Заранее заданной архитектуры нет. Новые компоненты вводятся только при подтверждённой необходимости.

Gaea и другие terrain tools выбираются только после актуального исследования и тестов; обязательного production backend нет. Собственный production terrain engine не является подходом по умолчанию. GUI, ручные промежуточные этапы и AI допустимы, если дают лучший воспроизводимый workflow. Production AI-результаты сохраняются вместе с доступными prompt/seed/settings; ручные действия и параметры документируются.

## Распространение карт

Карты распространяются бесплатно. Поддержка автора через Boosty
и добровольные пожертвования не должна быть условием доступа.

Платный ранний доступ, эксклюзивный игровой контент и продажа
карт не входят в текущую модель.

Перед использованием сторонних инструментов и ассетов
проверяются лицензии, условия распространения и правила
Bohemia Interactive. Для будущих игр условия проверяются заново.
## Этапы развития

- A — аудит готовых решений.
- B — небольшие практические проверки.
- C — сквозной production-test.
- D — минимальный рабочий pipeline.
- E — точечная автоматизация.
- F — собственный код только для подтверждённых пробелов.
- G — развитие по результатам реальной работы.
Source-данные не перезаписываются. Перед разрушительными изменениями нужны явное разрешение и Git/backup; обработка сначала проверяется на малом участке. Финальные художественные и gameplay-решения остаются за человеком.

Критерий успеха — качество и повторная применимость процесса создания миров, а не количество собственного кода. Практические инструкции для AI coding agents находятся в [AGENTS.md](AGENTS.md).
